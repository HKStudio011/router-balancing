# v1.12.3 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phát hành `v1.12.3` từ `master` bằng hai PR và GitHub Release workflow, với version, tag, notes và signed assets được xác minh đầy đủ.

**Architecture:** Đưa hotfix idle-timeout đã review vào `master` qua PR, tạo `release/v1.12.3` để bump version qua PR thứ hai, rồi tag đúng merge commit và publish GitHub Release. `release.published` kích hoạt workflow build/sign/upload.

**Tech Stack:** Git/GitHub CLI, GitHub Pull Requests/Actions/Releases, .NET 10 MAUI Windows, Go test/vet.

**Spec:** `docs/superpowers/specs/2026-11-25-v1.12.3-release-design.md`

## Global Constraints

- Version bắt buộc: `Version=1.12.3.0`, `ApplicationDisplayVersion=1.12.3`, `ApplicationVersion=33`, tag/release `v1.12.3` latest target `master`.
- Không force-push, không push trực tiếp lên `master`, không tạo release từ feature branch.
- Không đưa dirty work ngoài bảy file hotfix và hai tài liệu release vào PR.
- Không khẳng định đã sửa upstream/SOCKS EOF hoặc upstream availability.
- Bắt buộc đủ `router-balancing-v1.12.3-win.zip`, `.zip.sig` và `SHA256SUMS.txt` từ workflow chính thức.

## Review Focus

- PR diff chỉ chứa hotfix và tài liệu release; kiểm bằng `git diff master...HEAD` và `gh pr diff`.
- Merge commit phải được test lại dù không conflict.
- Ba version fields và assembly file version phải đồng nhất.
- Tag phải trỏ đúng `origin/master` chứa cả hai PR.
- Release chỉ hoàn tất khi workflow thành công và đủ signed assets.

---

### Task 1: Feature PR cho idle-timeout hotfix

- [ ] **Step 1: Kiểm scope và verification trên feature branch**

Chạy `git status --short`, `git diff --check`, full .NET tests, Windows build và Go test/vet. Xác nhận independent review không còn Critical/Important và các minor comments đã xử lý.

- [ ] **Step 2: Commit và push feature branch**

Commit bảy file hotfix cùng hai tài liệu release bằng `fix: default upstream idle watchdog off`, push `hotfix/upstream-idle-timeout-v1.12.3` lên origin.

- [ ] **Step 3: Tạo, kiểm và merge PR**

Tạo PR vào `master`; kiểm diff/checks. Không có check đỏ mới được merge bằng merge commit. Cập nhật local `master` bằng fast-forward pull và test kết quả merge.

### Task 2: Version PR v1.12.3

- [ ] **Step 1: Tạo release branch và bump đúng ba fields**

Từ `master` sau feature merge, tạo `release/v1.12.3`; chỉ đổi `Version=1.12.3.0`, `ApplicationDisplayVersion=1.12.3`, `ApplicationVersion=33`.

- [ ] **Step 2: Build và xác minh assembly version**

Chạy Windows build; xác nhận 0 warnings/errors và `FileVersion=1.12.3.0` từ DLL.

- [ ] **Step 3: Commit, push, kiểm checks và merge PR**

Commit `chore: bump version to 1.12.3`, tạo PR vào `master`, chờ checks rồi merge bằng merge commit. Cập nhật `master` và xác nhận version/ancestor.

### Task 3: Tag và publish release

- [ ] **Step 1: Viết notes theo đúng bằng chứng**

Nêu default off, preserved settings, applied-idle diagnostics và giới hạn không sửa external EOF. Ghi test/build/review evidence; hướng dẫn update qua app hoặc tải signed ZIP.

- [ ] **Step 2: Tạo/push annotated tag đúng master merge commit**

Kiểm tag chưa tồn tại, cả feature commit và version bump đều là ancestors của `origin/master`, rồi tạo/push `v1.12.3`.

- [ ] **Step 3: Publish GitHub Release**

Dùng `gh release create --verify-tag --target <origin/master> --latest`; xác nhận trigger là `release.published`.

### Task 4: Xác minh workflow và signed assets

- [ ] **Step 1: Theo dõi đúng Build Release run**

Tìm run theo tag `v1.12.3`, watch tới conclusion. Nếu fail thì điều tra, không báo hoàn tất.

- [ ] **Step 2: Kiểm metadata và assets**

Xác nhận release target/latest/notes và đủ ba assets ở trạng thái uploaded, size > 0, có SHA256. Không thay thế bằng artifact local.

- [ ] **Step 3: Báo cáo**

Báo release URL, workflow URL, version, tests và mọi giới hạn còn lại. Giữ feature/release branches cho audit.
