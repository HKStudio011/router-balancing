# v1.12.2 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phát hành `v1.12.2` từ `master` bằng hai PR và GitHub Release workflow, với version, tag, notes và signed assets được xác minh đầy đủ.

**Architecture:** Đưa Chat SSE branch đã review vào `master` qua PR, tạo `release/v1.12.2` để bump version qua PR thứ hai, rồi tag đúng merge commit và publish GitHub Release. `release.published` kích hoạt workflow build/sign/upload; không dùng artifact local thay cho pipeline chính thức.

**Tech Stack:** Git/GitHub CLI, GitHub Pull Requests/Actions/Releases, .NET 10 MAUI Windows, Go test/vet.

**Spec:** `docs/superpowers/specs/2026-11-25-v1.12.2-release-design.md`

## Global Constraints

- Version bắt buộc: `Version=1.12.2.0`, `ApplicationDisplayVersion=1.12.2`, `ApplicationVersion=32`, tag/release `v1.12.2` latest target `master`.
- Không force-push, không merge/push trực tiếp lên `master` để né PR, không xóa branch/tag của người khác, không tạo release từ feature branch.
- Không sửa build configuration để che bốn `NETSDK1082` mobile runtime-pack errors đã ghi nhận là pre-existing/environmental.
- Không tự tạo/upload ZIP chưa ký; bắt buộc đủ `router-balancing-v1.12.2-win.zip`, `.zip.sig` và `SHA256SUMS.txt` từ workflow chính thức.
- Release notes không khẳng định OpenCode Free/upstream availability hoặc full local solution build xanh.
- Không commit secret, dữ liệu request từ `E:\Data`, file DB/log hoặc `.superpowers` scratch.

## Review Focus

- Feature PR phải chứa đúng HEAD đã review `923598e` và hai docs release, không có file ngoài phạm vi — Task 1 kiểm PR diff và ancestor sau merge.
- Merge commit làm thay đổi tree dù không conflict vẫn phải được test — Task 1 chạy full .NET và Go suite trên `master` sau merge.
- Ba version fields và assembly file version phải đồng nhất — Task 2 kiểm XML và `FileVersionInfo` sau Windows build.
- Tag phải trỏ đúng `origin/master` chứa cả hai PR, không phải feature/release branch — Task 3 kiểm commit/ancestor trước publish.
- Release chỉ hoàn tất khi workflow thành công và đủ signed assets — Task 4 kiểm run conclusion, asset names/digests và latest bằng GitHub API.

- [ ] **Step 2: Xác nhận tag target và tạo/push annotated tag**

Kiểm tag chưa tồn tại local/remote. Lấy `$releaseCommit = git rev-parse origin/master` và xác nhận cả feature HEAD lẫn release bump đều là ancestors. Sau đó:

```powershell

```

- [ ] **Step 3: Publish release**

Dùng `gh release create v1.12.2 --verify-tag --target $releaseCommit --title v1.12.2 --notes-file <notes> --latest`. Lưu release URL. `release.published` phải trigger `Build Release`; không dùng `workflow_dispatch` thay thế.
