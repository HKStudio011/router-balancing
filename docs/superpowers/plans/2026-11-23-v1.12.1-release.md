# v1.12.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phát hành `v1.12.1` từ `master` bằng quy trình PR và GitHub Release workflow, với version, tag, notes và signed assets được xác minh đầy đủ.

**Architecture:** Đưa feature branch đã review vào `master` qua PR, tạo nhánh `release/v1.12.1` để bump version qua PR thứ hai, rồi tag đúng merge commit và publish GitHub Release. `release.published` kích hoạt workflow build/sign/upload; không dùng artifact local thay cho pipeline chính thức.

**Tech Stack:** Git/GitHub CLI, GitHub Pull Requests/Actions/Releases, .NET 10 MAUI Windows, Go test/vet.

**Spec:** `docs/superpowers/specs/2026-11-23-v1.12.1-release-design.md`

## Global Constraints

- Version bắt buộc: `Version=1.12.1.0`, `ApplicationDisplayVersion=1.12.1`, `ApplicationVersion=31`, tag/release `v1.12.1` latest target `master`.
- Không force-push, không merge/push trực tiếp lên `master` để né PR, không xóa branch/tag của người khác, không tạo release từ feature branch.
- Không sửa build configuration để che bốn `NETSDK1082` mobile runtime-pack errors đã ghi nhận là pre-existing/environmental.
- Không tự tạo/upload ZIP chưa ký; bắt buộc đủ `router-balancing-v1.12.1-win.zip`, `.zip.sig` và `SHA256SUMS.txt` từ workflow chính thức.
- Release notes phải giữ cảnh báo probe OpenCode Free `429 FreeUsageLimitError`; không hứa quota upstream đã hoạt động.
- Không commit secret, dữ liệu request từ `E:\Data`, file DB/log hoặc `.superpowers` scratch.

## Review Focus

- PR feature phải chứa đúng HEAD đã review `d0cda6750fa75b03f2791a0c86d47bcde5ea1b35` và docs release, không có file ngoài phạm vi — Task 1 kiểm PR diff và ancestor sau merge.
- Merge commit làm thay đổi tree dù không conflict vẫn phải được test — Task 1 chạy full .NET và Go suite trên `master` sau merge.
- Ba version fields và assembly file version phải đồng nhất — Task 2 kiểm XML và `FileVersionInfo` sau Windows build.
- Tag phải trỏ đúng `origin/master` chứa cả hai PR, không phải feature/release branch — Task 3 kiểm commit/ancestor trước publish.
- Release chỉ hoàn tất khi workflow thành công và đủ signed assets — Task 4 kiểm run conclusion, asset names và `isLatest`.

### Task 3: Tag v1.12.1 và publish GitHub Release

**Files:**
- Create outside repo: `%LocalAppData%/Temp/opencode/v1.12.1-release-notes.md`

**Interfaces:**
- Consumes: `origin/master` sau Task 2.
- Produces: annotated tag `v1.12.1` trên origin và published/latest GitHub Release kích hoạt workflow `release.yml`.

- [ ] **Step 1: Viết release notes đúng bằng chứng**

Notes gồm Fixes (clean EOF, title stop, NBSP + exact-name collision, UTC date test), Testing (1582/1582, Windows 0W/0E, Go test/vet, independent reviews), No database migration, Updating, `NETSDK1082` local exception và cảnh báo OpenCode Free `429 FreeUsageLimitError`. Không nói full solution build PASS hoặc Free đã hoạt động.

- [ ] **Step 2: Xác nhận tag target và tạo/push annotated tag**

Kiểm tag chưa tồn tại local/remote. Lấy `$releaseCommit = git rev-parse origin/master` và xác nhận cả feature HEAD lẫn release bump đều là ancestors. Sau đó:

```powershell
git tag -a v1.12.1 $releaseCommit -m "v1.12.1"
git push origin v1.12.1
```

- [ ] **Step 3: Publish release**

Dùng `gh release create v1.12.1 --verify-tag --target $releaseCommit --title v1.12.1 --notes-file <notes> --latest`. Lưu release URL. `release.published` phải trigger `Build Release`; không dùng `workflow_dispatch` thay thế.
